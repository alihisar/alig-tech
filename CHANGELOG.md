# Changelog

## Unreleased

- Shared PostgreSQL connection layer (ALIG-DB-003b, not wired into the application; SQLite is still the runtime): `ortak/pg.py` grew from the ALIG-DB-002 prototype into the layer that 003c-e will use. New: `islem(salt_okunur=, izolasyon=, statement_timeout_ms=, lock_timeout_ms=)` (read-only and isolation level, transaction-local timeouts); typed errors by SQLSTATE (`SerilestirmeHatasi` 40001, `DeadlockHatasi` 40P01, `YetkiHatasi` 42501, `ZamanAsimiHatasi` above `SorguIptalHatasi` 57014 and `KilitHatasi` 55P03, `SonucBelirsizHatasi` when the connection drops during COMMIT); `tekrarli_islem`, the only retry in the layer: allowed only for a read-only transaction or a write carrying an idempotency key, 1 to 10 attempts, capped exponential backoff with jitter, retries serialization failures and (with a connection factory) lost connections, never constraint, permission or timeout errors; a TLS policy (`sslmode`, `sslrootcert` passed to libpq; a network host requires `verify-full`, checked before libpq is called, no environment fallback for the host) and TCP keepalives; a lost connection is released at once and refuses reuse (no half-open state); the password (plain and escaped), conninfo-style `password=` and, with `gizli=True`, parameter values are masked in every message and in the `alig.pg` log (SQL text and parameters are never logged). No pool was built. New `tests/test_pg_baglanti.py`: 48 unit tests with a fake libpq and 20 tests on a PG16 temporary cluster (backend killed with `pg_terminate_backend`, rollback, statement and lock timeout, deadlock, serialization failure, permission denied, masking); they SKIP without PostgreSQL 16. The 25 prototype tests are unchanged and pass. Not tested: PG18, TLS over a real TCP connection, a reconnect to a restarted server, `idle_in_transaction_session_timeout` termination, Windows `libpq.dll`.
- Admin store on PostgreSQL (ALIG-DB-003d), not wired into the running panel: new `yonetim/depo_pg.py`, a second implementation of `yonetim/depo.py` (same function names; `con` is an `ortak/pg.Baglanti`) for users, sessions, login attempts, request statuses, cleanup (including the `denetle=True` maintenance cleanup, deletion and audit record in one transaction) and the panel counts; the SQLite modules are unchanged. Both audit chains (`yonetim_denetim`, `denetim`) are written with the SAME canonical format and verified by the very same `tarama.depo.denetim_durum` (run over PostgreSQL rows), so a chain written by one backend verifies under the other; writers are ordered by a per-chain `pg_advisory_xact_lock` taken before the tail is read (released at commit or rollback), with the schema's PRIMARY KEY and UNIQUE(onceki) as a second line; the application role has INSERT and SELECT only. If PostgreSQL is selected but not configured or unreachable the store raises (`YapilandirmaHatasi`, `BaglantiHatasi`); it never falls back to SQLite. `tests/test_yonetim_pg.py` (49 tests, real concurrent connections, temporary PG16 cluster, SKIP when PG16 is missing). Not done: `server.py`, `kullanici.py` and `bakim.py` still use SQLite; `ortak/pg_ayar.py` (003c) was tested only through a fake parser; PG18, TCP/TLS and password authentication were not tested. A transaction that writes both chains must take yonetim first, then tarama.
- Contact form, atomic rate limit and single-transaction deletion on PostgreSQL (ALIG-DB-003e, off by default; the SQLite runtime is unchanged and stays the default): new migration `db/sema/0006_sinir_sayac.sql` (`sinir_sayac`, window counters, own privileges); `ortak/sinir_pg.py` is a reusable limiter whose check and increment are one `INSERT ... ON CONFLICT DO UPDATE ... WHERE adet < limit RETURNING` statement (never above the limit under concurrent connections, keys stored as HMAC digests, expired windows cleaned up, 429 + `Retry-After`, no in-memory fallback) with a per-endpoint policy table; `ortak/pg_havuz.py` (bounded connection pool); `form/iletisim_pg.py` and a narrow dispatch in `form/server.py` (PostgreSQL only when `ortak/pg_ayar.py` reports a configuration; a configured but unreachable database stops the start and answers 503 + `Retry-After`, never SQLite); `ortak/silme_pg.py` deletes a company, its contact requests and its KVKK deletion request in one transaction. Tests ran on PostgreSQL 16 only; the other servers do not call the limiter yet.

- End-of-life PostgreSQL version rule (ALIG-SCAN-002, v5.1 §5.3): new rule `PG-MAINT-009` (maintenance, risk level Info, advisory only) reports a major version whose community support has ended, or ends within a window (default 180 days), at informational severity; it has weight 0 and a finding keeps full credit, so it does not lower the health score, and it never recommends an automatic change. The table lives in `tarama/eol.py` with the dates (13-18) taken from https://www.postgresql.org/support/versioning/ on 2026-11-16; versions older than 13 are reported as no longer supported without a date. The scan date is passed in from the scan document (no clock call in the evaluation). Window and dates can be overridden without a code change with the JSON file named in `ALIG_EOL_AYARI` (`docs/runbook.md`); an invalid file stops the scan and admin services from starting, like `ALIG_PUAN_AYARI`. `docs/kural-katalogu.md` (new rule row and the EOL table) and `docs/surum-matrisi.md` (new rule row) were regenerated with `tarama/uret_kurallar.py`. The collector catalog digest is unchanged (the rule reads the existing `pg_surum` check), so the digest pinned in `docs/surum-dogrulama.json` was not re-pinned and the real-server evidence tests are untouched. 33 new tests in `tests/test_eol.py`. Open points: the existing `PG-MAINT-001` (High after the end date, Medium within 90 days) is unchanged apart from reading the same table, so a version that has ended is reported by both rules (High and Info); whether to keep both is for Ali to decide. No minor-version-behind rule exists in the code, so none was added.
- Security headers (ALIG-SEC-002, v5.1 SEC-11): every response of the scan, portal and admin processes now carries `Cache-Control: no-store`, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy` and a CSP, from one place (`tarama/basliklar.py`; `form/server.py` keeps its own copy because it is standalone). HTML responses (reports, portal, panel, error pages) get a strict CSP with `script-src 'none'` and no inline style; the portal's looser CSP (`default-src 'self'`) was replaced by it; all other responses get `default-src 'none'`. nginx: `proxy_hide_header` for the headers the application also sends (two `X-Frame-Options` values are invalid in browsers; the application CSP is kept so the two policies intersect), and the www TLS redirect server now sends the header set and HSTS too. HSTS stays nginx-only (meaningless on loopback HTTP). New `tests/test_guvenlik_basliklari.py` (11 tests, every path x expected header). Not tested on a real nginx or in a browser.

- Health scan: history comparison (`tarama/gecmis.py`). The collector sends only the SHA-256 digest of the cluster identifier;
  an earlier scan by the same company of the same server (same role), if the retention period has not expired, is compared in the report:
  previous and new score, coverage change, and for each check new, worsened, persisting, resolved, unknown.
  If a previous problem cannot be measured in this scan it is not counted as resolved. It is also visible in the panel; viewing is written to the audit log.
- Health scan: six new PostgreSQL rules: autovacuum and track_counts, autovacuum disabled at table level,

- Health scan: health score (0-100) and evidence coverage (`tarama/puan.py`). Each rule carries a risk level; the score is the risk-weighted
  credit ratio. Unknown and Unavailable cost as many points as Failed: missing or lost data does not raise the score. In the report: summary lines,
  a category table and the checks that lower the score (finding and evidence gap separate);
  in the admin panel a Score column and the effective coefficients. The coefficients are set from a JSON file given by `ALIG_PUAN_AYARI`;
  with an invalid file the services do not start. In the report's evidence list yes/no values are now written in Turkish/English;
  in a report with no findings the space under the Findings heading is not left empty.
- Health scan: PostgreSQL version and privilege matrix. The collector and the direct connection read the server's major version, pick the query
  for that version, and never run the query on an unsupported version (a separate slot query for PostgreSQL 12). A new `pg_hesap`
  check reads the roles of the scan account; if the required role inside `pg_monitor` is missing the rule cannot be Passed (on a real PostgreSQL 16
  an unprivileged account could not see other sessions). On an untested version evidence confidence is at most medium. `tarama/surum_dogrula.py` verifies
  with three accounts on a real server; the result is in `docs/surum-matrisi.md`.
- Health scan: shared evidence model (`tarama/kanit.py`). Each rule produces a single status in every scan with a permanent ID (like PG-SEC-001):
  FAIL, WARNING, UNKNOWN, UNAVAILABLE, NOT_APPLICABLE, PASS; category, confidence level, source, observed
  values. PASS is never produced when data is missing, partial or corrupt. In the report a check results table, in the finding card the rule and source.
  The rule list is generated into `docs/kural-katalogu.md`. The `log_connections` list values of PostgreSQL 18 are recognized.
