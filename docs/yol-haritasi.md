in this file when it is finished. The order is in the "Daily plan" table below; a blocked item is skipped and the next unblocked item is taken.
For topics that await approval but do not block the work, work proceeds with a default value; the default is
written to the "Proceeding with a default" table so it can be changed with a single line. Blocking decisions (`docs/kararlar.md`) are not coded.

## Blocking decisions (Ali)

| Decision | What it blocks |
| --- | --- |
| Email sending method (a provider or its own server) | Registration email, sending of company verification, the general opening of Mode B |
| Hosting provider, server IP address, fixed egress IP | Going live, the customer firewall permission for Mode B |
| Legal texts: KVKK privacy notice, terms of use, Mode B connection consent | Going live |
| A real contact email and company details | The release tag (`--release` check) |
| Trying SQL Server on a real server | Publishing the SQL Server scan |
| Keeping a summary for comparison after a report is deleted (score and check statuses, no object names) and for how long; it entering the KVKK text | Comparison with a scan older than the retention period (30 days) |
| Logo and background images | Final form of the design |
| PostgreSQL driver, installation topology, cutover window, RPO/RTO (DB-K1, DB-K2, DB-K4, DB-K5) | The code and live part of the PostgreSQL migration (`docs/kararlar.md`) |
